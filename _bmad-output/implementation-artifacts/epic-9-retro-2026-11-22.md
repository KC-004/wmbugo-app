### Spec-to-implementation reconciliation
- **Account number in export (needs a human decision):** the spec asks for masked account numbers (last four, off by default). wmbugo stores no account numbers, so the `account_number` column is always empty, even with the switch on. Source: DW and the Epic 9 memory note. Propose: drop the switch or add an optional account-number field.
- **Epic 7 item 37 landed:** Story 9.9 adds `createCsvDocument` in `BackupFilesModule.kt` and the Android save dialog for export. Source: diff name list and commit `ffb43c6`.
- **Reference-based fingerprint has no account in it (checked against the code):** `csvFingerprint` in `packages/core/src/capture/csv/plan.ts:85-89` hashes `reference|direction|event type` only. Two accounts that reuse a reference such as `1` collide, and the second row is skipped as already recorded. This matches the LIR-03 wording quoted in the code comment, so it is as specced, but it is a silent data-loss path. Fix now (see action 1).
- **Other fingerprint and resume risks (unverified):** the no-reference fingerprint counts occurrences within one file, so an overlapping file that starts part-way through a day can duplicate; resume re-plans against the live ledger, so a transfer pair whose first leg was committed earlier loses its partner. Source: DW. Verify with a test before deciding.

### Review lenses
- **Correctness (open, from DW):** `held_pair` review rows show as plain Waiting with no way to answer (medium); `UndoImportReview` restores whole snapshots and loses later edits, and `undo_json` is parsed unguarded; `createForeignRow` drops the chosen account; `categoriesByName` is keyed by name only; `LinkAsTransfer` and `pairWithinFile` do not compare currencies; export `All time` and `This year` end today so future-dated entries are dropped, and the `time` column uses each entry's own timezone while the header names one.
- **Tolerance gaps (open, from DW):** Indian lakh grouping, Swiss `1'234.56` and `1 234.56` with a dot decimal are rejected; no `DD/MM/YY` or `YYYY/MM/DD`; `readCsv` lets an unterminated quote swallow the rest of the file with no warning and alters invalid UTF-8 and odd UTF-16 silently.
- **Verification gaps (open):** startup wiring (`sweepImportOrphans`, `PauseInterruptedImports`, expired-file removal) has no test; core export tests skip refund, adjustment, reversed and `AMOUNT_NOT_WRITABLE`; the Kotlin `pickCsvDocument`, `createCsvDocument` and `displayNameOf` have only mocked tests.
- **Hide-amounts:** no finding in this epic's evidence either way; the Epic 7 process item (41) is still open.
