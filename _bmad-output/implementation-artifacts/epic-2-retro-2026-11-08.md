## Process lessons

- **L1** Writing patch scripts with the Write tool and running them with `node` worked; two quoting failures were all in shell heredocs and nested escaping (bash heredocs, `\\"` inside script strings). Keep SQL in template literals and edit multi-quote strings with the Edit tool.
- **L2** The "one story, one device check, one commit" loop caught a UI issue the tests could not (header consistency, found by the user mid-epic). The user's mid-turn request for consistent headers became part of Story 2.4 rather than a new story: a shared component beats per-page fixes.
- **L3** The copy-catalogue test and the "money only through `<Amount>`" lint rule shaped the design twice (templates, split rendering). They cost a little time and prevented hard-coded money strings.
- **L4** The independent review is worth its cost for ledger logic: both medium logic bugs were interactions between stories (type change versus inclusion; statement edit versus paid), which no single story's tests could show.
