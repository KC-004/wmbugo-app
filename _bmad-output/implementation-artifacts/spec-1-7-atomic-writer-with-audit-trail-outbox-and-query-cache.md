## Intent

Implements the epic's Story 1.7 acceptance criteria (see epics.md).

## Implementation Notes

- Core `writer/`: event catalogue (type-checked emit, compile-time payload/catalogue match), `LedgerWriter` (one use case at a time via a promise queue, one transaction per run, audit rows per touched entity, outbox events, registered invariants, safe-integer parameter guard), `OutboxDispatcher` (ordered, at-least-once, serialised, marks delivered after handlers).
- Port: `SqlDatabase.transaction` / `UnitOfWork`. Migration 0002 (`audit_event`, `outbox`) generated by drizzle-kit from `writer.schema.ts`.
- Mobile: op-sqlite `transaction()` adapter, TanStack Query client (`networkMode: 'always'`) with per-event area invalidation, Zustand UI store with a policy test, outbox delivery kicked after each commit and on launch.
- Deviation: the AC says `BEGIN IMMEDIATE`; op-sqlite's `transaction()` issues `BEGIN TRANSACTION`. With one connection, the writer's own queue and op-sqlite's statement queue, nothing else can write or read mid-transaction, so IMMEDIATE adds nothing; revisit if a second connection is ever opened.
- Column order in `tx.query` comes from object key order; avoid numeric-looking column aliases.
- Verified on the Redmi (temporary smoke, since removed): 1 to 2 upgrade with a populated encrypted safety copy; 5 parallel use cases = 5 audit + 5 outbox rows; throw-midway left nothing; float param rejected; events delivered and cache invalidation handler ran.
