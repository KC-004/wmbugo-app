## Intent

**Problem:** A bank file's columns have to be told apart, every row checked before anything is saved, and a bank's layout remembered so the second import takes seconds.

**Approach:** Pure core (`capture/csv`): `guessMapping` (headings first, value shapes when there are none), `normalizeCsvRow` and `validateCsvRows` (fixed error codes and copy, a balance-column sign check, an account column mapped value by value), and saved formats: a `csv_format` table (migration 0027, capture-owned), a `SaveCsvFormat` use case and `findSavedFormat` by a header signature.

## Boundaries & Constraints

**Always:** one bad row never stops the others; a foreign-currency row is valid and marked foreign (never converted); a saved format holds the layout only, no row data; migrations are never edited once applied (0027 is new).

**Never:** treat an ambiguous day/month order as known; save a format under a name that is empty or over 80 characters.

## Implementation Notes

- The balance check works for statements written oldest first or newest first: it takes the better of the two orders, so a file with the right signs is confirmed either way and a file with the wrong signs fails both. `SIGN_LOOKS_REVERSED` needs more than half of the checkable pairs to disagree; `SIGN_CONFIRMED` needs every pair to agree; anything in between raises nothing.
- A signed amount of 0 is `MISSING_AMOUNT` (an entry cannot be for nothing); the spec does not name this case.
- A header signature normalizes the heading cells (case, accents, punctuation, spacing), so `Date ` and `date` are the same bank. Any different word, order, extra column or delimiter is a different signature.
- The saved account choice stores account ids (or `null` for `Don't import these rows`) per file value; the account column's values themselves are not stored in the signature.
- Event area `captures` was chosen for `CsvFormatsChanged` because the catalogue rule requires every event to invalidate something.
- Test fixtures use unambiguous dates (13/11/2026): 03/11/2026 reads as both 3 Nov and 11 Mar and correctly leaves the format open.
