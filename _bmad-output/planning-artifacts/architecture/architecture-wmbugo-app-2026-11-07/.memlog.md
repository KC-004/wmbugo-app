- (event) Create run from PRD v1.3.5 + addendum; coaching path; deliverable = build spine only; UX running in parallel
- (decision) AD paradigm: hexagonal core (pure TS: ledger, budgets, capture pipeline as fixed pipes-and-filters chain parse>normalize>match>classify>post) behind ports; adapters for SQLite, SMS, OCR, notifications, clock, share intent; feature-organised UI calls core only. Binds all. Prevents business logic in UI/adapters and RN/SQL leaking into domain. Alternatives rejected: classic layers (service dumping ground), event sourcing (too heavy for solo; audit rows suffice)
- (decision) AD boundary: pnpm workspace with packages/core (pure TS, no react-native dependency installed; tests in Node) and apps/mobile (RN CLI) depending on core. Prevents RN/SQL leaking into domain (compile-time). Fallback if Metro+pnpm painful in spike: single app + lint rule
- (decision) AD sign convention: posting signed_amount_minor + = money flows INTO the account, - = flows OUT, for every account type; card balance negative while owed, UI 'Card dues' = -balance; internal transfer postings sum to 0; expense/income = single posting on the user account, categories via splits summing to |amount|. Prevents opposite sign meanings across stories. Rejected: full double-entry (hidden world account, 2x rows), account-type sign (ambiguous)
- (decision) AD writes: every ledger mutation is a named command in core executed by a single serialized LedgerWriter inside one DB transaction (UnitOfWork port); invariants (transfer net 0, splits = amount, no duplicate confirmed, minor-unit safe ints) checked before commit; domain events (BudgetThresholdCrossed, CapturesAutoApproved, etc.) published only after commit to alert/learning/summary handlers; reads via query functions returning value + scope. Prevents ad-hoc writes, partial postings, pre-commit side effects
- (decision) AD storage: op-sqlite built with SQLCipher (package.json op-sqlite.sqlcipher=true — in pnpm workspace likely root package.json; encryptionKey at open) behind a Storage/UnitOfWork port in apps/mobile adapter; Drizzle ORM (op-sqlite driver, since v0.30.1) for schema, drizzle-kit generated numbered migrations bundled via Metro .sql support, typed queries; raw SQL allowed via sql helper for aggregates; core never imports Drizzle
- (version) Versions NOT confirmed by web search (registry snapshot suggests op-sqlite 15.x; SQLCipher 4.8.0 noted for op-sqlite 14.x); pin op-sqlite, drizzle-orm, drizzle-kit, react-native during M1 spike against npm/GitHub releases

- (decision) AD keys: random 256-bit DB key generated on first launch, held via react-native-keychain (Android Keystore), available after first unlock since boot, not auth/biometric-bound (matches NFR-10 v1.3.5); app lock = UI gate only; backups encrypted with separate passphrase-derived key (libsodium Argon2id + XChaCha20-Poly1305); DB key never logged/backed-up/exported. Rejected PIN-derived key (breaks locked capture, data loss on forgotten PIN)
- (decision) AD sms path: Kotlin SMS receiver (sms flavor only) stores/parses nothing; it enqueues a unique background job that runs the SMS catch-up (inbox since sms_cursor -> core capture pipeline -> LedgerWriter, fingerprint dedup); same path for live SMS, post-unlock, reboot, missed broadcasts; idempotent. Rejected: direct headless hand-off (second path), Kotlin parsing (duplicate rules, bypasses writer)
- (question) Spike: measure live-SMS-to-notification latency via background job on reference device vs NFR-16 (5s alive / 30s killed); confirm headless JS execution path for the job
- (decision) AD native UI: capture dialog is React Native (dialog-styled activity hosting the shared capture card); switch to native Kotlin only if spike measures open time > ~400 ms on reference device. Widget never reads the DB: after every commit the core writes a minimal widget snapshot (to-check count, amounts-allowed flag; no amounts when app lock on) that the widget renders; widget library (react-native-android-widget vs Glance) chosen in spike. Prevents second source of truth / key access from widget
