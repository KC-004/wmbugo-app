# Permissions

wmbugo asks for as little as it can. The release build declares no `INTERNET` and no `ACCESS_NETWORK_STATE` permission, so wmbugo does not send your data anywhere. (This is what the build declares and what the checks in CI verify; the proxy audit in `scripts/privacy/proxy-audit` is the check on a real phone.) Every permission that may ever be on the release allowlist (`scripts/android-permission-allowlist.json`) has a row below; a CI test fails when one has none. Every runtime request goes through the single `requestPermission(kind)` helper in `src/adapters/permissions.ts`, and none is requested during onboarding (spy test in `onboarding.test.tsx`).

| Permission | Kind | Feature that needs it | In-context rationale (shown before the system prompt) | What still works when denied | Revocation in Android settings |
| --- | --- | --- | --- | --- | --- |
| `POST_NOTIFICATIONS` | `notifications` | Budget alerts (Story 4.9) and bill reminders (Story 6.5) | Asked once, just in time: `Want a heads-up before a bill is due?` / `Get a nudge when a budget is nearly used?` Notifications never carry an amount. | Everything. Settings are kept; nothing is scheduled or posted. Bills and budgets show `Notifications are off for wmbugo` with `Open settings`. | Read again each time the app comes back to the foreground (no restart, no prompt, no crash): the screens re-read the state and show the denied wording. Reminders are scheduled again when it is granted. |
| `CAMERA` | `camera` | Snap receipt (Story 10.7): the in-app camera that photographs a receipt. Nothing is written to the gallery or shared storage. | Asked once, the first time the camera screen opens (never during onboarding): the system prompt, with `Pick a photo instead` already on the screen behind it. | Everything. The Add sheet, the Photo Picker path (`Pick a photo instead`, no permission) and `Enter it by hand` keep working; the camera screen reads `Camera is off for wmbugo` and offers `Open settings` once Android no longer shows the prompt. | Read again each time the app comes back to the foreground (no restart, no prompt, no crash): the camera screen shows the denied state, and the camera starts again once it is granted. |
| `USE_BIOMETRIC` | none (declared in the manifest; the system prompt needs no runtime request) | App lock (Story 8.3) and the `Confirm it's you` re-authentication: the system BiometricPrompt, a strong biometric or the device credential | Asked in context: the prompt is titled `Turn on app lock`, `Unlock wmbugo` or `Confirm it's you`. Nothing is requested at install or during onboarding. | App lock simply stays off. A phone with no screen lock shows `Set a screen lock on your phone first.` with `Open settings`. wmbugo is fully usable without app lock. | If the screen lock is removed after app lock was turned on, LockGate says it cannot ask the phone and offers `Open settings`; the data key is not tied to biometrics, so nothing is lost (AD-9). `USE_FINGERPRINT` is deliberately not declared, so on Android 8 and 9 the device credential is offered instead of the fingerprint. |
| `<applicationId>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | none | Added by AndroidX so only wmbugo can receive its own dynamically registered broadcasts | Never shown: it is not a runtime permission and has no prompt. | Not applicable. | Not applicable: it cannot be revoked. |

## Notes

- Permissions listed here but not yet declared in the manifest (the notification adapter is not installed yet) are documented ahead of time so the row exists when the adapter arrives.
- Android backup and phone-to-phone transfer exclude all wmbugo data (`allowBackup=false` and data-extraction rules).
- Files the user saves (backups, CSV and diagnostics exports) leave wmbugo's control; where they are put decides who can reach them. Backups stay encrypted with the passphrase.

## Backups and export files leave wmbugo's control (Story 8.7, BKP-006, BKP-007)

- **Android's own backup does not include wmbugo.** `allowBackup="false"` plus `backup_rules.xml` (Android 11 and earlier) and `data_extraction_rules.xml` (Android 12 and later, cloud backup and phone-to-phone transfer) exclude the database, photos, logs, staging and keys. A static test in `osBackup.test.ts` fails if the manifest attributes or the domains the rules exclude change; it reads the files as text, so it does not replace the on-device check. The on-device check (`adb shell bmgr backupnow app.wmbugo` and a device-to-device transfer, then looking for the database, photos, logs and keys) belongs to the release checklist.
- **A backup the person saves is theirs to place.** Backup, CSV and diagnostics files are written through Android's save dialog (Storage Access Framework, no permission) to the place the person chose. Saved to a cloud folder, a file leaves the phone: it is still encrypted with the passphrase (a backup) or contains only what the person previewed (diagnostics), but where it goes decides who can reach it. wmbugo never keeps a copy.
- **No permission is needed** to make or restore a backup: the save dialog and file picker hand over one document.

## Exported CSV files are not encrypted (Story 9.9, EXP-001)

- **An exported CSV is plain text.** Export CSV writes the person's entries, or a summary of their accounts, through Android's save dialog (Storage Access Framework, no permission) to the place they chose. The file is not encrypted and leaves wmbugo's control: whoever can reach that place can read it. The app says so in a confirm sheet before it writes anything, asks `Confirm it's you` first when app lock is on, and deletes a partly written file if the person cancels.
- **Account numbers are never stored.** The optional `account_number` column holds at most the last four digits, masked (`••4821`), and only when the person turns the switch on. wmbugo keeps no account number today, so the column is empty.
- **Cells that would run as a formula are neutralised.** A cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return is written with a leading `'`.
- **Imported bank files are kept encrypted and local** (Story 9.8): a copy lives in app-private storage with the device file key, for 30 days by default, never uploaded, and removed by Erase everything. There is still no `INTERNET` permission.
